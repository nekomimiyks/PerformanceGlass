# v0.1.13の性能調整と検証

GPT-6.2-Astra（正式モデルID `gpt-6.2-astra`）へソース解析・差分案・回帰レビューを依頼し、提案をローカルで実装・計測して採否を判断しました。モデル自身の実測ではありません。追加ライブラリ、描画品質の低下、更新間隔の延長はありません。

## 採用した変更

- グラフ集約用の配列を再利用し、同じ幅での再描画時の確保・解放を省略。バケット初期化を履歴ロックの外で行います。保持容量は従来の最大幅4096列で上限があります。
- 密な履歴では、通信スケールの最大値を集約済みバケットから求めます。疎な履歴ではサンプル走査と同時に求め、短期間・横長表示での退行を避けます。
- グラフ専用表示や高さの足りない表示では、表示しない数値欄の文字整形・UTF-16変換・文字幅計測を行いません。

数値欄の文字幅を再利用する案も比較しましたが、大きな通常表示の改善を確認できなかったため採用していません。CPU/GPU等の取得方法、1秒更新、欠測・ピーク・実時刻のギャップ表現を維持しています。

## 履歴集約の比較

同じPC・同じRust/MinGW最適化条件で、43,201件の固定サンプルを使用。30回の準備後に300回を測定し、新旧を交互に3セット実行した中央値です。新実装は実際の描画と同じバッファ再利用経路を計測しています。単位は1回あたりのµsです。

| 期間／幅960px | v0.1.12 | 調整後 | 短縮 |
| --- | ---: | ---: | ---: |
| 1分 | 4.030 | 3.779 | 約6% |
| 10分 | 15.154 | 12.851 | 約15% |
| 60分 | 73.007 | 58.829 | 約19% |
| 6時間 | 423.931 | 339.674 | 約20% |
| 12時間 | 850.882 | 698.898 | 約18% |

幅280・960・1920pxと全5期間の15条件で、中央値の退行はありませんでした。これは履歴集約単体の値で、アプリ全体やPC全体のCPU使用率が同じ割合で下がることを意味しません。

## 描画の比較

同一のGNUリリースビルド条件・固定データで、30回準備後に300フレームを連続描画し、新旧の実行順も変えて比較しました。最終採用した処理では、高さ60px・幅280px・12時間表示の中央値が約1.68msから約1.36msへ短縮しました（約19%）。

大きい通常表示の全体時間は変動が大きく、短縮を確認できていません。通常の12時間表示では中央値が約4.88msから約5.14msとなった組もあります。すべての表示条件で高速になるとはしていません。数値欄の文字幅再利用案はこの比較を踏まえて外しました。

## 正しさと追加の枠切替

- 旧実装を参照実装として残し、新旧の全バケットの件数・最小・最大・和・最初と最後の時刻・通信スケールをビット単位で比較。
- 12時間超のリング巻き戻り、全5期間、幅0/1/2/280/960/1920/4096/4097、通信系列の表示4通り、NaN・無限大・境界・ピーク・時刻ギャップ、再利用後の空履歴を検証。
- 性能調整段階の既存描画画像17点は、旧版とピクセル単位で一致しました。
- ダブルクリック・F11・Escで枠を切り替える際は、描画グラフの物理寸法と画面座標を保持します。最小ウィンドウ寸法が必要な場合は余白を残し、グラフを拡大しません。
- 高DPI・狭い幅でも軸とラベルが収まる余白へ切り替えます。
- Windowsの同期通知中に長命な排他的状態参照を保持しないよう、コマンド・メニュー・ツールチップ処理を整理。Astraが指摘した枠変更・ツールチップ親通知の再入経路を修正しました。
- 単体テスト16件と、12言語のWin32 UI検証で確認します。UI検証は96/120/144/192/288/384 DPI相当のレイアウト、グラフ寸法と画面座標の保持、最小280×60px、辺・角のリサイズ判定、ネイティブのホバー通知、言語・テーマ切替、GDI/USERオブジェクト数を対象にします。

数値はこのPCと測定条件での結果です。実モニター間の移動や、すべての端末・ドライバで同じ結果を保証するものではありません。初回Store申請中のv0.1.10は取り消していません。
